## 二、实时数据帧结构（353 字节）

每帧固定 **353 字节**：帧头 + 长度域 + 载荷 + CRC。

```
┌────────┬──────────────┬───────────────────────────────┬──────────┐
│ Header │    Length    │           载荷数据             │   CRC    │
│ 1 byte │   2 bytes    │  （字段见 §三 映射表）          │  2 bytes │
│  0x80  │  0x5F 0x01   │      偏移 3 … 350             │ 351–352  │
└────────┴──────────────┴───────────────────────────────┴──────────┘
  [0]       [1]  [2]          [3 … 350]                   [351][352]
```

| 字段 | 偏移 | 长度 | 说明 |
| --- | --- | --- | --- |
| Header | 0 | 1 byte | 帧头，固定 `0x80` |
| Length | 1 | 2 bytes | 载荷长度，**小端序**，固定值 **351**（`0x5F 0x01`） |
| Payload | 3 | 348 bytes | 数据字段（偏移 3–350），见 §三 |
| CRC | 351 | 2 bytes | CRC-16（当前跳过校验，见 §八） |

> **说明**
> - 长度域值 351 = 整帧 353 − 2（即「长度」不含末尾 2 字节 CRC）。
> - 协议手册标称帧长 355 字节，**实际串口每帧比手册短 2 字节（353）**，接收端以 353 为准。
> - 设备记录的二进制「完整帧」为 355 字节（见 §九.3.2），与串口实时帧存在 2 字节差异，详见 §十一。

## 三、载荷字段映射表

下表偏移均以**帧头 `0x80` 为偏移 0** 计算。未列出的字节为保留 / 未使用。

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 1 | Header | u8 | 帧头 `0x80` |
| 1–2 | 2 | Length | u16 LE | 载荷长度 = 351 |
| 6–9 | 4 | DeviceTimeSec | u32 | 设备内部时钟，Unix 秒（**字节序见 §十一**） |
| 10 | 1 | BlockStatus | bitfield | 电极 / 信号状态位（见 §四） |
| 11 | 1 | EventNumber | u8 | 临床事件序号（0 = 无事件） |
| 12 | 1 | EventType | u8 | 临床事件类型（见 §五枚举） |
| 13 | 1 | **CSI** | u8 | 麻醉深度指数 0–99，等效 BIS；`0xEE`/`0xFF` = 无效 |
| 14 | 1 | **BS** | u8 | 爆发抑制比 0–100（%）；`0xFF` = 无效 |
| 15 | 1 | **SQI** | u8 | 信号质量指数 0–100（%）；`0xFF` = 无效 |
| 16 | 1 | BlackImpedance | u8 | 黑色电极（电极 3）阻抗等级 1–10，`15` = 阻抗过高 |
| 17 | 1 | WhiteImpedance | u8 | 白色电极（电极 1）阻抗等级 1–10，`15` = 阻抗过高 |
| 18 | 1 | **EMG** | u8 | 肌电信号指数 0–100；`0xFF` = 无效 |
| 20 | 1 | AlarmHigh | u8 | 上限报警阈值 |
| 21 | 1 | AlarmLow | u8 | 下限报警阈值 |
| 22–121 | 100 | **EEG[100]** | i8 × 100 | EEG 波形，100 个有符号字节，直接为 µV（量程 ±127 µV） |
| 125 | 1 | **NOX** | u8 | 伤害感受 / 镇痛指数 0–99；`0xFF` = 无效 |
| 126 | 1 | DeltaPowerDb | i8 | δ 频带功率（dB，有符号） |
| 127 | 1 | ThetaPowerDb | i8 | θ 频带功率（dB，有符号） |
| 128 | 1 | AlphaPowerDb | i8 | α 频带功率（dB，有符号） |
| 129 | 1 | BetaPowerDb | i8 | β 频带功率（dB，有符号） |
| 130 | 1 | GammaPowerDb | i8 | γ 频带功率（dB，有符号） |
| 131 | 1 | EOG | u8 | 眼动指数 0–100 |
| **132–175** | **44** | **DSA[44]** | u8 × 44 | **密度谱阵列**：1–44 Hz 每 1 Hz 一格的无符号功率强度（0–255），由设备给出 |
| 176 | 1 | **SEF95** | u8 | 谱边缘频率 95%，范围 1–44 Hz |

> **DSA 字段说明**（旧版文档遗漏，此处补齐）：
> - 偏移 132–175 共 44 字节，`Dsa[f-1]` 对应频率 f Hz 的功率强度，量程 0–255。
> - 该值由**设备端**直接计算，上位机不做 FFT，仅存储 / 显示。
> - 电极报警或失效帧（`BlockStatus & 0x82 != 0`）时，DSA 按设备约定清零（见 §四）。

## 四、电极状态位与 DSA 清零

`BlockStatus`（偏移 10）位定义：

| 位 | 掩码 | 字段 | 含义 |
| --- | --- | --- | --- |
| bit 1 | `0x02` | ElectrodeAlarm | 电极脱落报警 |
| bit 3 | `0x08` | ImpedanceHigh | 阻抗偏高 |
| bit 7 | `0x80` | ElectrodeInvalid | 电极失效 |

**DSA 清零条件**：当 `BlockStatus & 0x82 != 0`（即 ElectrodeInvalid 或 ElectrodeAlarm 任一置位）时，该帧 DSA 数组按设备约定**整体清零**，不参与频谱显示。

此外，当 `BlackImpedance >= 15` 或 `WhiteImpedance >= 15` 时，亦判定为阻抗过高。

## 七、采样率与自适应检测

| 项目 | 值 |
| --- | --- |
| 每包 EEG 样本数 | 100 samples |
| 设备内部 EEG 采样率 | ≈ 100 Hz（实测，自适应） |
| 包发送频率 | ≈ 1 packet/s |
| EEG 转换 | 有符号字节直接为 µV（无额外比例换算），量程 ±127 µV |

**采样率自适应**（`NsmSerialService.DetectSampleRate`）：
- 接收端测量相邻数据包到达时间间隔（毫秒）；
- 反推采样率：`采样率 = 100000 / 平均包间隔(ms)`，结果钳制在 **50–500 Hz**；
- 累计 ≥ 5 个有效包间隔后锁定，此后 `SampleRate` 返回锁定值，不依赖界面手选的标称值。
- 回放 / 模拟器固定返回 `100`。

## 八、帧同步与容错

实时串口接收采用「滑动窗口搜索帧头」策略（`ProcessBuffer`）：

1. 在缓冲区内搜索帧头 `0x80`；
2. 移除帧头之前的无效字节（假帧头前导噪声）；
3. 缓冲区不足整帧长度（353 字节）时，等待更多数据；
4. 校验长度域 `[1..2]`（小端）是否等于 **351**，否则**丢弃当前帧头 1 字节**并重新同步；
5. **CRC 校验当前跳过**：设备使用非标准 CRC 变体（与标准 CRC-16/CCITT 存在差异），待厂商确认算法后再启用；
6. 解析载荷、提取字段、对外发布 `NSMDataReceived`；
7. 从缓冲区移除已消费的 353 字节，继续搜索下一帧；
8. 缓冲区内无 `0x80` 时清空缓冲区。

> 与 AFE4490 指脉协议的差异：NSM 帧仅用**单一字节帧头 `0x80` + 长度域**同步（未校验帧尾），
> 因帧长固定 353 且长度域 351 强校验，误同步概率可接受。

## 九、数据记录文件格式（.nsm）

`.nsm` 记录文件存在 **三种格式**，回放端按「首字节 + 长度域」自动识别（见 §十）。

| 格式 | 来源 | 判别 |
| --- | --- | --- |
| JSON Lines | 本机录制（`NsmRecordingService`） | 首个非空字节 ≠ `0x80` |
| 128 字节紧凑记录 | 设备采集（至 NOX，无频带功率/EOG/SEF95/DSA） | 首字节 `0x80`，长度域 ≠ 351 |
| 355 字节完整帧 | 设备采集（全字段） | 首字节 `0x80`，长度域 = 351 |

### 9.1 JSON Lines 格式（本机录制）

- 每行一个 JSON 对象（紧凑、无缩进），对应一个 `NSMDataPacket`；
- 行首字符为 `{`，按 `System.Text.Json` 反序列化回 `NSMDataPacket`；
- 字段与 §三 一致，另含以下**录制专用字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| LocalTimestamp | DateTime | 接收时刻（本机时钟），回放据此重建时序 |
| EEGSamplesUv | double[100] | 100 个 EEG 样本（µV） |
| Dsa | byte[44] | 密度谱阵列（无则为空数组） |
| PulseWaveIr | short[]? | 红外脉搏波**交流分量**（已减 DC），约 125 样本/包，无脉搏仪或老文件为 null |
| PulseWaveRed | short[]? | 红光脉搏波交流分量（已减 DC） |
| IrDc | int | IR 通道本包**直流基线**（均值） |
| RedDc | int | RED 通道本包直流基线（均值） |

> **脉搏波存储策略**：录制时只存「AC 交流分量 + DC 直流基线」，不存原始绝对值，
> 兼顾体积（short 而非 int）与可还原性。回放用 `AC + DC` 还原绝对值，走与实时完全相同的计算链（见 §十.4）。

### 9.2 128 字节紧凑记录（设备采集）

- 定长 **128 字节**：帧头 `0x80` … NOX（偏移 125）共 126 字节 + 末尾 2 字节 CRC；
- **不含** 频带功率、EOG、SEF95、DSA；
- 字段偏移与 §三 前半段（偏移 0–125）完全一致；
- 长度域（偏移 1–2）**不等于 351**（用于与完整帧区分）。

### 9.3 355 字节完整帧（设备采集）

- 定长 **355 字节**，含全部字段（频带功率 / EOG / SEF95 / DSA）；
- 长度域（偏移 1–2）= 351；
- 字段偏移与 §三 一致（含 DSA 132–175、SEF95 176）。

## 十、文件回放读取

`NsmPlaybackService` 实现 `INsmDataSource`，与真实串口 / 模拟器共用同一套界面绑定。

### 10.1 格式识别与读取

1. 读文件首个字节：`0x80` → 二进制记录，否则 → JSON Lines；
2. 二进制记录再读偏移 1–2 的长度域：= 351 → 355 字节完整帧，否则 → 128 字节紧凑记录；
3. **整文件一次性读入内存**（`Connect` 同步完成），解析为 `List<NSMDataPacket>`，
   使整场数据在连接返回后立即可用（报告可预加载整场，不受回放进度限制）；
4. 二进制记录逐条解析，跳过首字节非 `0x80` 的未对齐 / 损坏记录。

### 10.2 回放时序重建

- 回放按相邻包 `LocalTimestamp` 差值（原始时间间隔）重放：
  - 实时 / JSON 录制：`LocalTimestamp` 为接收时刻；
  - 二进制记录：`LocalTimestamp` 由 `DeviceTimeSec`（Unix 秒）换算，为 0 时退回当前时间。
- 单包延时钳制在 50–2000 ms，再除以回放倍率（0.1–64×，可实时调整）。

### 10.3 进度与拖动

- 对外提供 `ProgressChanged`（当前帧索引 / 总帧数 / 已播时长 / 总时长）；
- `SeekToIndex` 支持任意跳转；拖动后触发 `Seeked`，界面据此重建 `[0, index)` 的累积图表（趋势 / DSA / 事件），随后从目标帧继续推送。

### 10.4 脉搏波重建

- 回放遇到含 `PulseWaveIr` 的包时，逐样本还原绝对值：
  `IR绝对 = PulseWaveIr[i] + IrDc`，`RED绝对 = PulseWaveRed[i] + RedDc`；
- 以**包时间戳**喂入 `PulseOximetryProcessor`，与实时共用同一条 SpO₂ / 脉搏 / SPI 计算链；
- 保证回放的血氧 / 脉搏 / SPI 与趋势、DSA 等面板共用同一时间轴对齐。

## 十一、帧长与字节序说明（实现差异）

> 以下两点为当前实现中已识别的差异，文档如实记录，供后续统一。

**1. 串口帧 353 vs 记录完整帧 355**

| 链路 | 帧长 | 长度域 | CRC 位置 |
| --- | --- | --- | --- |
| 实时串口 | 353 | 351 | 351–352 |
| 记录完整帧 | 355 | 351 | （末尾 2 字节） |

手册标称 355 字节，实际串口短 2 字节（353）；设备记录文件中的「完整帧」按 355 字节存储。
接收 / 回放分别以各自帧长为准，长度域均为 351。

**2. DeviceTimeSec 字节序不一致**

| 链路 | 读取方式 | 字节序 |
| --- | --- | --- |
| 实时串口（`NsmSerialService.ParsePacket`） | `buf[6] | buf[7]<<8 | buf[8]<<16 | buf[9]<<24` | **小端**（buf[6] 为低位） |
| 回放二进制（`NsmPlaybackService.ParseRecord`） | `buf[6]<<24 | buf[7]<<16 | buf[8]<<8 | buf[9]` | **大端**（buf[6] 为高位） |

两者对同一 4 字节字段采用相反字节序，属待统一项。回放注释标注为「设备时间为大端 Unix 秒」。

| 区间 | 含义 |
