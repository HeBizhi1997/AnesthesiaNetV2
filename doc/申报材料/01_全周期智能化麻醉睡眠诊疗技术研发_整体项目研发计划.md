## 1. 项目概述

### 1.1 项目名称

全周期智能化麻醉睡眠诊疗技术研发

### 1.2 项目背景

麻醉与睡眠在神经电生理机制上高度同源——两者均表现为意识水平、脑电活动模式、自主神经张力与呼吸调控的可量化变化。临床上，麻醉深度监测（防止术中知晓与过深麻醉）、围术期睡眠呼吸障碍（OSA）筛查、镇静镇痛管理、睡眠门诊诊疗等业务长期分散于不同科室、依赖不同设备，缺乏统一的数据采集标准与全周期闭环管理手段。

主要痛点：

- **监测维度割裂**：脑电（EEG/BIS）、血氧、心率、呼吸、体动、情绪、量表、用药等数据来自异构设备，难以多模态融合分析。
- **进口设备依赖**：高端麻醉深度监测（如 BIS、Entropy）核心算法封闭、耗材昂贵，国产化与自主可控需求迫切。
- **诊疗周期断裂**：院前评估、院中监测、院外随访三段割裂，患者离院后无持续监督手段，镇静/睡眠药物使用与疗效缺乏客观反馈闭环。
- **智能化程度低**：现有监护以阈值报警为主，缺乏基于深度学习的趋势预测、事件预警与个体化指导。

### 1.3 项目定位——"全周期"内涵

本项目以"院前—院中—院外"全周期、"采集—监测—指导—随访"全闭环为定位，构建一套覆盖麻醉睡眠诊疗全流程的智能化技术体系，由三大子系统协同：

| 子系统 | 应用场景 | 对应物理形态 |
|--------|----------|--------------|
| **麻醉睡眠院内管理系统** | 院内科室管理、数据中枢、医嘱/量表/用药、诊疗指导 | 服务器 + Web/桌面端 |
| **麻醉睡眠监护仪** | 手术室、睡眠门诊、ICU 镇静、DISE 等床旁实时监测 | 医疗器械（软硬件一体） |
| **远程线上小程序** | 院外患者远程监测、随访、用药监督、依从性管理 | 微信小程序 + 云端 |

### 1.4 现有技术基础（项目起点）

本项目并非从零起步，已具备可演示的原理样机与算法基础（技术成熟度 TRL 4–5）：

- **核心算法 AnesthesiaNetV3**：基于原始脑电的实时 BIS 推断模型，在 VitalDB 数据集（1,749 例手术、139,849 条训练序列）上验证 **BIS MAE 4.57**，麻醉阶段分类准确率 **98.6%**，手术刺激事件检测 AUC **0.816**。
- **38 维麻醉睡眠电生理特征集**：含慢振荡（0.1–0.5 Hz，深睡/深麻标志）、Sigma 纺锤波功率、delta-alpha 相幅耦合（丙泊酚 GABA_A 指纹）、爆发抑制比（BSR 三级阈值）、排列熵、谱斜率等。
- **院内监测客户端原型**：基于 WPF/.NET 8 的实时监测仪表盘，已实现 7 通道分频波形、DSA 频谱图、BIS/SE/RE/fNox 趋势、睡眠分期与催眠图、SpO₂/ODI 血氧分析、用药记录、镇静评分（Ramsay/RASS/MOAA-S）、体位记录、报告生成（JSON/CSV）。
- **采集硬件**：已完成基于 ADS1299（256 Hz、双通道前额 EEG）与 NSM 模组、HKG-07D 指夹式脉搏血氧模组的串口集成与通信协议实测。
- **推理服务**：Python FastAPI + PyTorch 推理后端，提供 EEG 预处理、特征提取、模型推理 HTTP 接口。

本项目目标是将上述原理样机推进至**符合医疗器械法规的定型产品、完成临床验证并取得注册证、形成全周期产品矩阵**。

## 2. 国内外现状与必要性分析

### 2.1 麻醉深度监测

国际主流为美敦力 BIS、GE Entropy 等，算法封闭、耗材绑定。国内已有少量自研脑电意识深度产品，但在原始脑电深度学习建模、爆发抑制与刺激事件检测、个体化校正方面仍有差距。本项目以自研深度学习模型替代经验公式，具备自主可控优势。

### 2.2 睡眠监测

金标准为多导睡眠图（PSG，需 16+ 导联、整夜、人工判图），昂贵且可及性差。便携式睡眠监测（HSAT）与可穿戴设备精度有限。本项目以前额 EEG + 血氧多模态实现自动睡眠分期（AASM 五分期）+ OSA 筛查，定位"轻量化、可床旁、可院外延伸"。

### 2.3 远程监护与随访

现有慢病管理小程序多为问卷/打卡，缺乏客观电生理与血氧数据回传及智能预警闭环。本项目通过院外可穿戴/便携采集 + 小程序 + 云端 AI，实现镇静/睡眠诊疗的院外延续与依从性监督。

### 2.4 必要性小结

- **临床价值**：降低术中知晓与麻醉过深风险，提升围术期 OSA 筛查率，构建睡眠诊疗闭环。
- **产业价值**：核心算法与设备国产化，降低耗材成本，形成软硬件 + 云 + 小程序的可复制产品体系。
- **数据价值**：建成多模态麻醉睡眠专病数据库，支撑持续的算法迭代与临床研究。

## 3. 研究目标与考核指标

### 3.1 总体目标

研制具有自主知识产权的全周期智能化麻醉睡眠诊疗技术体系，完成监护仪医疗器械注册、院内管理系统部署应用、远程小程序上线，建成多模态专病数据库，形成可产业化的产品矩阵与标准规范。

### 3.2 量化考核指标

| 类别 | 指标 | 目标值 |
|------|------|--------|
| **算法精度** | BIS 预测 MAE（对比金标准监护仪） | ≤ 5.0 BIS 单位 |
| | 麻醉阶段分类准确率 | ≥ 95% |
| | 睡眠分期与人工判图一致性（Cohen's κ） | ≥ 0.75 |
| | OSA 筛查灵敏度 / 特异度（对比 PSG） | ≥ 85% / ≥ 80% |
| **监护仪硬件** | EEG 通道数 / 采样率 | ≥ 2（预留 8）/ ≥ 250 Hz |
| | 输入参考噪声 | ≤ 1 μVpp（典型） |

| | 安全与 EMC | 符合 GB 9706.1 / GB 9706.226 等 |
| **系统平台** | 院内系统并发监测床位 | ≥ 50 床 |
| | 端到端监测时延 | ≤ 2 s |
| | 数据可靠存储与回放 | 100% 原始数据可回溯 |
| **远程小程序** | 院外数据回传成功率 | ≥ 99% |
| | 异常事件推送时延 | ≤ 30 s |
| **合规成果** | 监护仪医疗器械注册证 | 取得（II 类，目标 III 类预研） |
| | 软件著作权 | ≥ 6 项 |
| | 发明专利申请 | ≥ 4 项 |
| | 标准/规范/论文 | ≥ 3 项 |
| **临床验证** | 多中心临床试验受试者例数 | ≥ 300 例（含睡眠门诊 + 手术室） |

## 4. 主要研究内容（三大子系统）

### 4.1 子系统一：麻醉睡眠院内管理系统

定位为全周期的**数据中枢与诊疗指导平台**。

- **数据接入与汇聚**：对接监护仪、麻醉机、HIS/LIS/EMR、量表系统，统一多模态数据模型与时序数据库。
- **量表与评估**：术前评估量表（STOP-BANG、Epworth、ASA 分级）、镇静量表、情绪量表的数字化录入与评分。
- **用药与医嘱**：结构化用药记录（药名/剂量/途径/速率）、医嘱管理、药物-意识-效应关联分析。
- **诊疗指导与决策支持**：基于多模态趋势的事件预警、个体化镇静建议、报告自动生成。
- **数据治理**：脱敏、权限分级、审计日志、专病数据库构建（支撑算法迭代与科研）。

### 4.2 子系统二：麻醉睡眠监护仪（本项目核心医疗器械）

定位为**床旁多模态实时监测设备**（软硬件一体，按医疗器械全流程研发，详见配套文档《麻醉睡眠监护仪研发计划》）。

- 多模态采集：EEG（爆发抑制、频段功率、纺锤波）、SpO₂/脉搏、心率/HRV、呼吸、体动、体温等。
- 实时智能指标：BIS、频谱熵 SE/RE、伤害指数 fNox、睡眠分期、催眠图、ODI/T90 血氧分析。
- 信号质量诊断、电极阻抗检测、自动告警、会话记录与回放。

### 4.3 子系统三：远程线上小程序

定位为**院外远程监测与监督**入口。

- 院外便携采集设备数据回传（蓝牙/4G/5G）。
- 患者端：睡眠/血氧报告查看、用药提醒、量表填写、依从性打卡。
- 医生端：远程查看趋势、异常事件推送、随访管理、复诊提醒。
- 云端 AI：边云协同推理、长期趋势分析、风险分层。

### 4.4 三系统协同关系

```
            ┌────────────────────────────────────────────┐
            │        麻醉睡眠院内管理系统（数据中枢）       │
            │   多模态数据库 · 量表/用药/医嘱 · 决策支持    │
            └───────▲──────────────────────────▲─────────┘
                    │ 院内实时                  │ 院外回传/随访
            ┌───────┴────────┐         ┌───────┴────────┐
            │  麻醉睡眠监护仪  │         │  远程线上小程序  │
            │ (手术室/睡眠门诊)│         │  (院外/可穿戴)   │
            └────────────────┘         └────────────────┘
              院中实时监测                 院前评估 + 院外随访
```

## 5. 总体技术路线与创新点

### 5.1 总体技术架构

```
采集层  EEG前端(ADS1299) + SpO2/脉搏 + 多参数 + 可穿戴(院外)
   │（串口/蓝牙/网络，统一数据协议）
边缘层  信号质量评估 · 预处理(滤波/陷波/去伪迹) · 边缘特征提取
   │
智能层  AnesthesiaNetV3 多任务深度模型
        ├ BIS 回归头（麻醉深度）
        ├ 阶段门控头（诱导/维持/苏醒/术前）
        ├ 睡眠分期头（W/N1/N2/N3/REM，AASM）
        ├ 刺激/事件检测头
        └ PK/PD 药效编码（药物-效应预测）
   │
平台层  院内管理系统 · 时序数据库 · 决策支持 · 报告引擎
   │
应用层  监护仪界面 · 院内 Web/桌面 · 远程小程序 · 云端随访
```

### 5.2 关键技术与创新点

1. **原始脑电端到端深度学习麻醉深度建模**：以 WaveEncoder（扩展卷积 + 爆发抑制检测层）+ LNN/GRU 时序核 + 阶段门控 BIS 头替代封闭经验公式，自主可控、可解释（38 维电生理特征旁路）。
2. **麻醉-睡眠统一多任务模型**：共享 CNN 编码器，同时输出 BIS、麻醉阶段、睡眠分期、刺激事件，实现"一套模型、两类场景"。
3. **多模态生理-药理融合**：PK/PD 药代动力学编码器接入实际给药数据，预测给药后 BIS 下降/回升曲线，支撑个体化镇静。
4. **信号质量自适应推理**：SQI 惯性机制——信号质量下降时冻结时序隐状态，抑制伪迹导致的指标跳变。
5. **边云协同全周期闭环**：院中高频实时、院外低功耗回传、云端长期趋势分析的统一数据与模型管线。

### 5.3 技术成熟度演进路线

| 阶段 | TRL | 形态 |
|------|-----|------|
| 现状 | 4–5 | 原理样机 + 回顾性数据验证 |
| 中期 | 6 | 工程样机 + 前瞻性小样本验证 |
| 结题 | 8 | 定型产品 + 注册检验 + 多中心临床 + 注册证 |

## 6. 研发阶段划分与实施步骤（八阶段）

> 本项目按医疗器械设计控制（ISO 13485 / IEC 62304 / ISO 14971）与软硬件协同开发流程组织，划分为八个阶段。各阶段设评审门（Phase Gate），通过后方进入下一阶段。

### 阶段一　项目立项与可行性论证（M1–M3）

**目标**：完成立项决策与顶层设计。

- 市场与临床需求调研：访谈麻醉科、睡眠中心、ICU 临床专家；梳理使用场景与用户需求（UN）。
- 竞品与专利分析：BIS/Entropy 等竞品技术与专利布局分析，自由实施（FTO）初评。
- 法规路径研究：确定监护仪医疗器械分类（II 类为主，AI 决策支持模块按《人工智能医疗器械注册审查指导原则》评估是否升 III 类）、注册检验项目、临床评价路径。
- 可行性研究报告：技术可行性、临床可行性、经济可行性、风险初评。
- 顶层设计：总体架构、三子系统接口规范、数据模型、技术指标分解。
- **立项评审（Gate 1）**：批准立项，冻结需求基线与产品定义。

**交付物**：立项报告、可行性研究报告、用户需求文档（URS）、法规与标准清单、项目总计划与质量计划。

### 阶段二　关键技术攻关与技术验证（M2–M9，与阶段一部分并行）

**目标**：验证核心技术可行性，形成原理样机迭代。

- EEG 采集前端关键技术：低噪声前端、电极阻抗检测、共模抑制、爆发抑制段采集验证。
- 算法关键技术：在现有 AnesthesiaNetV3 基础上完成睡眠分期头、PK/PD 头的多任务联合训练；模型轻量化与边缘部署（量化/裁剪）。
- 多模态时间同步：EEG/SpO₂/多参数毫秒级时间对齐与统一时间戳方案验证。
- 关键技术验证报告：在受控数据集与少量真实采集数据上验证各关键指标。
- **技术验证评审（Gate 2）**：确认关键技术可行，关闭高风险技术不确定项。

**交付物**：关键技术验证报告、算法基线模型与评测报告、原理样机（迭代版）、技术风险清单。

### 阶段三　设计与开发策划（M3–M5）

**目标**：建立设计控制体系，完成设计输入。

- 设计开发计划（DDP）：阶段、活动、评审、验证/确认、职责、资源。
- 设计输入（Design Input）：将 URS 转化为产品技术要求（PRD/产品技术要求草案），含性能、安全、EMC、软件、网络安全、可用性、生物相容性（接触电极）要求。
- 标准清单冻结：GB 9706.1、GB 9706.226（脑电）、YY/GB 血氧、IEC 60601-1-2、IEC 62304、ISO 14971、GB/T 25000.51 等。
- 风险管理启动（ISO 14971）：风险管理计划、初始危害分析。
- 网络安全与数据合规策划：依《医疗器械网络安全注册技术审查指导原则》《个人信息保护法》《数据安全法》。
- **设计输入评审（Gate 3）**。

**交付物**：设计开发计划、产品技术要求草案、风险管理计划、网络安全方案、可用性工程计划（IEC 62366）。

### 阶段四　软硬件研发与系统集成（M5–M20）

**目标**：完成三子系统工程样机开发与集成。

并行三条研发线：

- **监护仪研发线**（详见配套文档）：硬件（采集前端/主控/电源/结构/EMC）、嵌入式固件（采集/通信/自检）、上位机软件、AI 推理引擎。按 IEC 62304 软件安全分级（建议 B 级）实施单元/集成测试。
- **院内管理系统研发线**：数据接入网关、时序数据库、多模态数据模型、量表/用药/医嘱模块、决策支持与报告引擎、权限与审计。
- **远程小程序研发线**：小程序前端、云端服务、边云协同推理、消息推送、随访管理、数据加密传输。

工程化要求：版本控制、CI/CD、代码评审、缺陷追踪、可追溯性矩阵（需求↔设计↔测试）。

- **设计评审（Gate 4，分模块）**：各子系统工程样机评审。

**交付物**：工程样机（监护仪）、院内系统与小程序 Beta、软件设计文档、单元/集成测试报告、可追溯性矩阵、软件版本基线。

### 阶段五　数据采集与算法训练（M6–M24，贯穿）

**目标**：建成多模态专病数据库，完成算法训练与冻结。

- 数据采集方案与伦理：制定采集 SOP、知情同意、伦理审查（IRB）。
- 多源数据：公开数据（VitalDB、Sleep-EDF、SHHS、MASS）+ 合作医院前瞻性采集（手术室麻醉、睡眠门诊 PSG 对照、镇静场景）。
- 数据标注：人工 BIS/睡眠分期金标准标注、事件标注、质控双人复核。
- 数据治理：脱敏、质控、版本化数据集、训练/验证/测试划分（按患者分层，防泄漏）。
- 算法训练与评估：多任务训练、域适应（手术室→睡眠门诊）、个体化校正；冻结临床版模型并形成算法验证报告（含偏倚、泛化、子组分析）。
- **算法冻结评审（Gate 5）**：临床版模型锁定，禁止训练后变更（满足注册要求）。

**交付物**：多模态专病数据库、数据集说明书、算法训练与验证报告、冻结模型与版本记录。

### 阶段六　设计验证与确认（V&V）（M18–M28）

**目标**：证明产品满足设计输入（验证）并满足用户需求（确认）。

- 设计验证（Verification）：逐项验证产品技术要求（性能、电气安全、EMC、软件功能、网络安全、报警）。
- 设计确认（Validation）：在模拟使用或真实使用环境下验证临床适用性，含可用性确认（IEC 62366，形成性 + 总结性测试）。
- 系统联调：三子系统端到端联调（监护仪→院内系统→小程序）。
- 软件确认：IEC 62304 验证、回归测试、网络安全测试（渗透/漏洞扫描）。
- **设计验证与确认评审（Gate 6）**。

**交付物**：设计验证报告、设计确认报告、可用性总结报告、系统联调报告、网络安全测试报告。

### 阶段七　型式检验与注册检验（M26–M32）

**目标**：通过具备资质（CMA/CNAS）的医疗器械检验机构注册检验。

- 检验送样：定型样机送检（如江苏省医疗器械检验所等）。
- 检验项目：电气安全（GB 9706.1）、电磁兼容（GB 9706.1-2/IEC 60601-1-2）、脑电专用安全（GB 9706.226）、性能、软件、网络安全。
- 产品技术要求注册：定稿并经检验机构预评。
- 整改与复测：依检验意见整改。

**交付物**：注册检验报告、产品技术要求（注册稿）、整改记录。

### 阶段八　临床验证、注册申报与成果转化（M28–M36）

**目标**：完成临床评价/试验，取得注册证，落地应用。

- 临床评价路径确认：同品种比对 + 临床试验（依产品分类与指导原则）。
- 多中心临床试验：方案设计（与金标准 BIS 监护仪/PSG 头对头）、伦理审查、入组、随访、统计分析、临床试验报告（详见第 8 节）。
- 质量体系核查准备：医疗器械生产质量管理规范（GMP）现场核查准备、设计转换（量产工艺）。
- 注册申报：向省级/国家药监局提交注册申请（注册检验 + 临床评价 + 技术文档 + 风险管理 + 说明书标签）。
- 成果转化：院内系统部署、小程序上线、监护仪小批量试产、知识产权布局、标准制定。
- **结题评审（Gate 7）**：达成考核指标，项目验收。

**交付物**：临床试验报告、注册申报资料、注册证（或受理/审评中证明）、量产工艺文件、用户手册、结题报告。

## 7. 数据采集与治理方案

### 7.1 数据来源

| 来源 | 用途 | 规模（建议） |
|------|------|--------------|
| VitalDB 等公开手术数据 | 麻醉深度算法基线 | 已用 1,749 例 |
| Sleep-EDF/SHHS/MASS 睡眠库 | 睡眠分期域适应 | 数千夜 |
| 合作医院手术室前瞻采集 | 临床验证 + 个体化 | ≥ 150 例 |
| 睡眠门诊 PSG 对照采集 | 睡眠分期/OSA 验证 | ≥ 100 夜 |
| 镇静/DISE/ICU 场景 | 场景泛化 | ≥ 50 例 |

### 7.2 数据标准与治理

- 统一多模态时序数据模型与术语（对接 HL7/FHIR 思路）。
- 采集 SOP + 知情同意 + 伦理审查；数据脱敏与最小化采集。
- 质控：信号质量评分、双人标注复核、版本化数据集、防患者级泄漏的数据划分。
- 数据安全：分级权限、加密存储传输、审计日志，符合《数据安全法》《个人信息保护法》《信息安全技术 健康医疗数据安全指南》。

## 8. 临床验证方案

### 8.1 总体设计

- **试验类型**：前瞻性、多中心、对照临床试验。
- **场景分层**：手术室麻醉深度监测、睡眠门诊睡眠分期/OSA 筛查、镇静镇痛深度管理。
- **对照（金标准）**：麻醉深度——上市 BIS 监护仪头对头；睡眠分期/OSA——标准 PSG + 人工判图。

### 8.2 主要/次要终点

- 主要终点：BIS 预测一致性（Bland-Altman 一致性界限、MAE）；睡眠分期一致性（κ）；OSA 筛查灵敏度/特异度。
- 次要终点：术中知晓发生率、报警准确性、可用性满意度、不良事件。

### 8.3 样本量与统计

- 依主要终点效应量与把握度（power ≥ 0.8，α = 0.05）估算，建议总例数 ≥ 300。
- 统计方法：一致性分析、ROC/AUC、κ 系数、非劣效检验。

### 8.4 伦理与质量

- 各中心伦理委员会审查（IRB）、知情同意、临床试验质量管理规范（GCP）、监查与稽查、数据核查、试验注册（如 ChiCTR）。

- 麻醉睡眠监护仪：按脑电/多参数监护，预判 **II 类**；若 AI 模块提供独立诊断/治疗决策，按指导原则可能升 **III 类**。立项阶段向药监部门预沟通确认。
- 院内管理系统/小程序中的纯管理功能一般不作为医疗器械；其中含 AI 辅助诊断/分期的软件模块（SaMD）按医疗器械软件单独评估。

## 12. 风险分析与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 算法泛化不足（手术室→睡眠门诊） | 临床指标不达标 | 域适应 + 多中心数据 + 子组分析 + 个体化校正 |

| 监护仪 EMC/电气安全不达标 | 注册受阻 | 早期 EMC 摸底、预测试、专业结构/EMC 设计 |

| 数据安全合规 | 法律风险 | 数据分级、加密、脱敏、等保测评、合规审查 |
| 进口器件供应 | 量产风险 | 关键器件国产替代评估、双供应商 |
