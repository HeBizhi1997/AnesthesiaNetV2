# ADS1299 采集板 通信协议与调用方式(实测修订版)

> 适用硬件:LK-M1299 单电极差分板(USB 桥 Silicon Labs CP210x)
> 依据:**厂商上位机 `ADS1299.exe` 反编译源码 + 真实串口实测**
> ⚠ **本文修正了厂商 `.docx`(EEG-ads1299-通信协议 20260529.docx)中的关键错误**(读/写位极性相反),以本文为准。

## 1. 串口参数

| 项 | 值 | 说明 |
|---|---|---|
| 波特率 | **230400** | 固定 |
| 数据位 / 校验 / 停止位 | 8 / None / 1 | |

## 2. 帧结构

请求帧(主机→设备)与响应帧(设备→主机)结构相同,仅帧头/帧尾不同:

```
┌──────┬───────────┬──────┬──────┬─────────┬───────────┬───────────┬──────┐
│ 帧头  │  长度(LE)  │ 地址  │ 命令  │ 头校验   │   数据      │  数据校验  │ 帧尾  │
│ 1B   │   2B      │ 1B   │ 1B   │  1B     │   N 字节    │   1B      │ 1B   │
└──────┴───────────┴──────┴──────┴─────────┴───────────┴───────────┴──────┘
 [0]    [1] [2]     [3]    [4]    [5]       [6..6+N-1]   [6+N]       [7+N]
```

| 字段 | 字节 | 说明 |
|---|---|---|
| 帧头 Header | [0] | 请求 = **`0xA5`**,响应 = **`0xAA`** |
| 长度 Length | [1..2] | **uint16 小端**,= **整帧总字节数 = N + 8**(N=数据长度) |
| 地址 Address | [3] | `0x00`=广播(本板一直用 0x00) |
| 命令 Command | [4] | 见 §3(注意读写位极性) |
| 头校验 HdrChk | [5] | `XOR(Length_lo, Length_hi, Address, Command)` 即 `XOR(byte[1..4])` |
| 数据 Data | [6..] | 变长,N 字节,具体由命令决定 |
| 数据校验 DataChk | [6+N] | `XOR(所有 Data 字节)`;N=0 时为 `0x00` |
| 帧尾 Tail | [7+N] | 请求 = **`0x5A`**,响应 = **`0x55`** |

## 3. 命令字与**读/写位**(关键修正)

命令字低 7 位是命令码;最高位 bit7 是读/写标志。

> ### ⚠ 极性与文档相反(实测/反编译为准)
> ```
> 写命令 (WRITE):  cmd & 0x7F     → bit7 = 0
> 读命令 (READ) :  cmd | 0x80     → bit7 = 1
> ```
> 厂商 `.docx` 写的是"bit7=1 为写",**是错的**。按文档实现会让 `开始采集`/`配置参数` 被固件当成"读",**板子永远不会启动采集**(冷启动无数据的根因)。

| 命令码 | 读/写 | 名称 | 数据 |
|---|---|---|---|
| `0x00` | R | 读固件版本 | 无 → 响应 ASCII,如 `V1.0.0 20260103` |
| `0x01` | R | 读硬件版本 | 无 → 响应 ASCII |
| `0x02` | W | 设备重启 | `[0x01]` |
| `0x03` | W | 连接状态/保活 | `[0x00]`断开 / `[0x01]`已连接 / `[0x02]`保活(每 1s 发一次) |
| `0x04` | W | 开始/停止采集 | `[0x00]`停止 / `[0x01]`开始 |
| `0x05` | R/W | 采样参数 | 写:见 §4;读:无数据,响应回当前参数 |
| `0x06` | R(响应) | 采样数据 | 仅设备主动上报,见 §5 |

### 3.1 常用请求帧(已算好校验,可直接发)

| 命令 | 字节序列(hex) |
|---|---|
| 停止采集 | `A5 09 00 00 04 0D 00 00 5A` |
| 开始采集 | `A5 09 00 00 04 0D 01 01 5A` |
| 保活(连接) | `A5 09 00 00 03 0A 02 02 5A` |
| 读固件版本 | `A5 08 00 00 80 88 00 5A` |
| 读硬件版本 | `A5 08 00 00 81 89 00 5A` |
| 读当前参数 | `A5 08 00 00 85 8D 00 5A` |
| 配参(500sps,±375mV,CH1,差分) | `A5 0E 00 00 05 0B F4 01 0C 01 00 01 F9 5A` |

## 4. 采样参数(命令 `0x05` 写)

数据区 6 字节:

| 偏移 | 字段 | 类型 | 取值 |
|---|---|---|---|
| 0..1 | 采样率 rate | uint16 LE | **250 / 500 / 1000 / 2000**(sps) |
| 2 | 放大倍数 gain | byte | 见下表(由量程换算) |
| 3 | 通道使能 ch_en | byte | bit_i = CH(i+1);如仅 CH1 = `0x01`,全开 = `0xFF` |
| 4 | 输入开关 inputSwitch | byte | `0x00`电极采集 / `0x01`内部短路 / `0x02`测试信号 |
| 5 | 模式 mode | byte | `0x00`单端 / `0x01`差分 |

### 量程 ↔ gain 对照(ADS1299 PGA)

| 量程 | gain |
|---|---|
| ±4.5 V | 1 |
| ±2.2 V | 2 |
| ±1.1 V | 4 |
| ±750 mV | 6 |
| ±560 mV | 8 |
| **±375 mV** | **12** ← 默认 |
| ±186 mV | 24 |

**默认配置**:rate=500,gain=12(±375mV),差分。

### 参数响应帧(命令 `0x05`,设备→主机)

数据区:`[rate u16][gain][ch_en][ch_sw][mode]`(≥6 字节时 mode 有效)。
上位机据此**校验配置是否生效**(比较 rate / gain / mode 与请求一致)。

## 5. 采样数据帧(命令 `0x06`,设备→主机)

- 帧头 `0xAA`,命令 `0x86`(=`0x06|0x80`),帧尾 `0x55`。
- 长度 = `8 + ch·n·4`,其中 **ch = 8(固定 8 通道)**,n = 本帧每通道样本数。
- 数据区:`float32 小端`,**8 通道交织** `[ch0_s0, ch1_s0, … ch7_s0, ch0_s1, …]`,单位 **µV**,固件钳位 ±4,500,000 µV。
- 解析:`float_count = (Length - 8) / 4`;`样本数 = float_count / 8`。

### ⚠ 本板固件实测特性(与文档不符,但真实)
1. **永远交织 8 通道**,无视 `ch_en`;只有 **CH1(index 0)** 是真实差分电极信号,**CH2–CH8 恒为 0.0**(填充)。→ 解码时**固定按 8 路解交织,取 index 0**。
2. **无视采样率请求**:实际约 **250 Hz/通道**(总吞吐 ~2000 float/s ÷ 8),ACK 里却回 500。→ 上送下游(Python)的采样率按 **250** 标定,否则频率轴错位(50Hz 会被折叠到 ~31Hz)。

## 6. 接收端解析状态机

```
1. 在缓冲区中找帧头 0xAA
2. 取 Length = byte[2]<<8 | byte[1];若 < 8 或 > 上限 → 丢 1 字节重找
3. 缓冲不足 Length → 等更多数据
4. 校验帧尾 byte[Length-1] == 0x55;不符 → 丢 1 字节重找
5. (可选)校验 HdrChk = XOR(byte[1..4]) == byte[5]、DataChk
6. 按 (byte[4] & 0x7F) 分发:6=数据帧,5=参数响应,0/1=版本
7. 移除该帧,继续
```
> 收到任意有效帧即把"连接超时计数"清零;连续多个保活周期无帧 → 判定断开。

## 7. 调用 / 启用流程(关键)

> 厂商上位机的真实启动序列(反编译 `BtnStart_Click`),**不是简单的"连接→配参→开始"**,而是带**校验和重试**:

```text
打开串口 (DTR=false, RTS=false)
  └─ 可选: 发"读参数(0x85)"查询设备当前配置

开始采集 (最多重试 5 次):
  loop:
    1. 发 停止采集 (0x04 写 [0])            ; 等 100 ms
    2. 若参数尚未确认:
         发 采样参数 (0x05 写 [...])         ; 等 200 ms
         读参数响应, 校验 rate/gain/mode 是否与请求一致
         不一致 → continue (重试)
         一致 → 标记参数已确认
    3. 清空接收缓冲
    4. 发 开始采集 (0x04 写 [1])
    5. 观察 CH1 数据是否在增长 (5×100ms 内至少增长 2 次)
         增长 → 启动成功, 退出 loop
         不增长 → continue (重试)
  超过 5 次仍失败 → 提示"采集失败, 请重启设备"

运行中: 每 1 秒发 保活 (0x03 写 [2])
停止:   发 停止采集 (0x04 写 [0])
关闭:   关串口
```

要点:
- **先停后配再启**(STOP → PARAMS → START),不要直接 START。
- **配参后必须读回校验**,否则可能配置未生效就启动 → 不出数据。
- **启动后用"数据是否在增长"确认**,失败则重试整个序列。
- 全程 **DTR/RTS 保持 false**。

## 8. 电极/导联状态判定(信号有效性)

| 状态 | 原始 std(µV) | 含义 |
|---|---|---|
| `lead_off` | **> 1500** | 电极未接入/导联脱落(高阻悬空,满幅噪声 ~10⁴µV) |
| `ok` | ~5 – 150(典型) | 正常脑电(含工频时原始可达数百 µV,仍算 ok) |
| `flat` | **< 0.5** | 无信号(短路/断开,近平线) |
| `saturated` | — | ADC 削顶/饱和(clip>10%) |

信号无效(非 ok)时,下游意识指标(qCON/qNOX/SQI)应置"信号无效",不应在噪声上输出读数。
实现见 Python 端 [`eeg_preprocessor.py`](../EEGMonitor/EEGProcessingService/preprocessing/eeg_preprocessor.py) 的 `electrode_status` / `signal_valid`。

## 9. 校验和示例(供自测)

以"配参 500sps/±375mV/CH1/差分"为例,数据区 `[F4 01 0C 01 00 01]`:
- Length = 6 + 8 = 14 = `0x000E` → `0E 00`
- Command(写 0x05) = `0x05`
- HdrChk = `0E ^ 00 ^ 00 ^ 05` = `0x0B`
- DataChk = `F4^01^0C^01^00^01` = `0xF9`
- 整帧:`A5 0E 00 00 05 0B  F4 01 0C 01 00 01  F9 5A`

## 10. 与厂商 .docx 的差异汇总

| 项 | 厂商 .docx | 实测/反编译(本文,正确) |
|---|---|---|
| 读/写位 bit7 | 1=写,0=读 | **0=写,1=读**(相反) |
| DTR/RTS | 未提 | **必须 false** |
| 启动方式 | 连接→配参→开始 | **停止→配参→校验→开始→确认数据(重试)** |
| ch_en | 按位使能各通道 | 固件无视,**恒发 8 通道**,仅 CH1 有效 |
| 采样率 | 250/500/1000/2000 | 固件无视请求,**实际 ~250Hz/通道** |
